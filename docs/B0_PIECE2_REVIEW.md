### Columns of the CSVs

| Column | Meaning |
|---|---|
| `mother_pdg`, `key`, `names` | the B (511, 521 and their antiparticles) and the final state, as PDG codes and as names |
| `dec_lines` | the decay-file line numbers of the final state, in its own block |
| `bf_mc` | rate of this final state in the decay file |
| `pdg_class` | `measured` (a PDG value exists; c derived, except for zero-BF lines, which have none), `limit` (only an upper limit), `none` (no PDG entry, or `unmeasured`, or vetoed), `inclusive` (X_u ℓν and similar) |
| `how` | where c comes from: `exact` = a PDG entry for exactly this final state; `product` = a PDG entry of the form B(B → X Y) × B(X → …); `node` = the line is the direct line of a multi-body PDG entry and takes what is left of it after the other lines; `isospin` = the corrected BF of the isospin partner in the other B block (exception); `half_limit` = c = limit/2 ± limit/2 (exception); `veto` = c = 0 (exception); empty = no c |
| `pdgids` | the PDG entries used. `S042.n` is a B⁰ entry, `S041.n` a B⁺ entry; the number is PDG's permanent identifier of the entry |
| `bf_pdg`, `bf_pdg_err` | the PDG value and error that were used (for `isospin` rows: the transferred value for this line) |
| `c`, `sigma_c` | c = BF_PDG / BF_MC and its uncertainty (absolute) |
| `pull` | (c − 1) / sigma_c: how many σ the decay file is away from PDG |
| `f_res_mc` | for a multi-body final state: the fraction of it that the decay file produces through resonances (1 − direct line / total) |
| `f_res_pdg` | the same fraction according to PDG: the sum of PDG's resonant sub-entries divided by the total. A lower bound, since PDG may not list all resonances. Much larger than `f_res_mc` means the decay file puts into a phase-space line what is really resonant |
| `c_prod` | c from the product entries of the line, whenever it has some (equal to c when the product is the source) |
| `extra_rel` | relative uncertainty added by an `extra_uncertainty` exception |
| `flags` | warnings, see below |
| `alt_pdgids` | with `node_ambiguous`: the other PDG entry this line could have taken its c from |
| `fed_nodes` | the measured PDG final-state entries this line feeds (with at least 10 % of its rate) |
| `node_info` | for each of them: "id: PDG value ± error, decay-file sum, after c (pull)" |
| `unclosed_nodes` | with `node_not_closed`: the entries the decay file still misses by more than 3σ after all c are applied |
| `twin_pdgids` | with `flavor_twin`: a PDG entry that matches this line if the K⁰/K\*⁰ flavor or the charge assignment is ignored; the entry suggests the decay file wrote the wrong flavor |
| `max_share` | review file only: the largest share of the exclusive yield that this mode has in any of the 72 sample tables (12 samples × comb D side, comb ℓ side, hadB × charged, neutral) |
| `max_share_table` | the table where that happens |
| `n_top95` | in how many of the 72 tables the mode is among those that cover 95 % of the exclusive hadronic yield |
| `why` | why the row is in the review: `top95` (large yield), `pull` (c more than 3σ from 1), `flag` (carries a warning) |

Flags, current meaning:

| Flag | Meaning |
|---|---|
| `unmeasured` | the line feeds a measured PDG total but has no entry of its own (or is kept as a gap mode): c = 1, σ_c = 1 |
| `remainder_unstable` | the remainder that gave a direct line its c is less than 1σ from 0 (σ of the remainder > c) |

| `limit_capped` | a line without c that the decay file puts above its own PDG limit; counted as limit/2 ± limit/2 in remainders and in the closure |
| `above_limit` | the decay file (or c × BF) is above a PDG limit of the line |
| `c_extreme` | c outside 1/3 … 3 (not set for vetoed lines) |
| `measurement_conflict` | the c rests on measurements in tension; σ_c widened (P1) |

| `flavor_twin` | see `twin_pdgids` |
| `resonance_mismatch` | PDG's resonant fraction exceeds the decay file's by more than 0.3 |
| `multi_ks` | PDG entry with several K_S: no c |
| `tau`, `zero_bf`, `exception_applied` | τ mode; zero-BF line of the decay file; an exception touched the line |

## 2. Rules as implemented

Summary of the rules of `scripts/tools/pdg_match.py` (module docstring) as they stand after all
decisions; the reasons are in the record (sections named in brackets) and in section 1.

- *Unit of comparison:* the PDG entry (node), not the decay-file line. BF_MC of an entry is the sum
  over the exclusive B lines of BF_line × P(line → final state of the entry), following the decay
  file's own sub-decays.
- *Folding:* a daughter is replaced by its decays if it is broad (width ≥ 10 MeV, lifetime 0) and not
  named in the entry. Narrow states (D\*, D_s\*, D_s0\*, J/ψ, ψ(2S), η, ω, φ, Σ_c(2455), D_s1(2536),
  K_S⁰, ...) and η_c, η_c(2S), χ_c0 are not folded, except into the entries whose measurement
  includes them (`fold` exceptions, P6, record 5i and 5k).
- *Neutral kaons:* K⁰, K̄⁰, K_S⁰ and K_L⁰ are one symbol; an entry with one K_S⁰ (K_L⁰) is multiplied
  by 2; entries with two or more are flagged `multi_ks` and give no c.
- *Leptons:* PDG "ℓ" entries are compared with the e and with the μ final state, each with the full
  value.
- *Sources of c, in this order* (M1, G3/G4; record 2 and 5a):
  1. `exact`: a measured entry for exactly this final state, fed by no other line;
  2. `product`: B(B → X Y) × B(X → …) against BF_line × BF_sub of the decay file (independent product
     entries combined with inverse-variance weights);
  3. `node`: only for the direct (phase-space) line of a measured multi-body total: c = (total −
     other lines after their c) / BF, clamped at 0 (`remainder_clamped`); lines without a c are
     subtracted as 1 ± 1, lines above their own limit as limit/2 ± limit/2; σ_c adds 20 % of the
     subtracted part for interference.
  A line that reaches a total only through a resonance never takes a c from it (M1).
- *Measured non-resonant parts* (P2, record 5i): where the decay file has a line for every other
  measured component, the PDG non-resonant entry is the source of the direct line (`nonres_direct`,
  how `nonres`); the total becomes a closure check. Otherwise the direct line keeps the remainder.
- *Measurements outside PDG* (P5): `external` (how `external`), refused once PDG has an entry.
- *Entries not used* (`exclude_node`): window-restricted measurements (P3), entries in conflict or
  with doubtful content (E5, E6, E9, E14, P4); register in section 3.
- *Lines without a c:* `unmeasured` (feeds a measured total, no entry of its own) c = 1 ± 1;
  `limit` c = 1; `none` (no PDG entry) c = 1 without σ (N1 open); `inclusive` (X_u ℓν, X_s) c = 1.
- *Anti-B rows* take the result of their B⁰/B⁺ conjugate; where the two blocks have different BFs,
  the corrected BF is transferred (`cp_transfer`, G6).
- *Checks, flags only:* closure of every measured total after c (`node_not_closed`),
  `resonance_mismatch`, `above_limit`, `flavor_twin`, `measurement_conflict`, `c_extreme`,
  `block_asymmetric` (flag list in section 0).


## 3. The exceptions file

`Samples/dec/pdg_exceptions.json` holds the corrections to the automatic matching: 79 entries (28 until P2–P7 were implemented on 2026-11-18),
each with an `action` and a `reason` (with the PDG text where a PDG entry is concerned). It is read
every time the table is built; without an entry, the automatic rule applies. An entry names a PDG
entry (`pdgid`) or a decay-file final state (`mother`, `key`); a final state must be in the B⁰ or the
B⁺ block (the loader refuses anything else): the anti-B rows follow their conjugate. Actions:

| Action | Effect |
|---|---|
| `rewrite` | the text of the PDG entry is replaced by `description` before it is parsed. For misprints and incomplete texts in the PDG listing, and for entries that are sums of charge states |
| `exclude_node` | the entry is not used at all |
| `fold` / `no_fold` | for one final-state entry: add or remove resonances that are counted as part of it (`fold` used since P6; `no_fold` not used) |
| `force_class` | set the class of a final state by hand; applied before the totals are split, so the line takes no c from a total |
| `isospin` | a B⁰ (B⁺) line takes the corrected BF of its isospin partner in the other block (divided or multiplied by the lifetime ratio 1.076), which must have an exact or product c |
| `direct_line` | a line that reaches a PDG total through a resonance is treated as the direct line of that total (the decay file routes the whole final state through it) |
| `extra_uncertainty` | a relative uncertainty added in quadrature to σ_c; an optional `flag` is added to the line (`measurement_conflict` in P1) |
| `half_limit` | a line that the decay file puts above its own PDG upper limit takes c = limit/2 ± limit/2 (class limit) |
| `veto` | a line that should not exist (wrong flavor) takes c = 0 ± 0 (class none); its anti-B conjugate inherits it |
| `nonres_direct` | (P2) a measured PDG non-resonant entry is the source of the direct line of its total: c = value/BF, how `nonres`, flag `nonres_source`; the total only enters the closure check. The entry names `pdgid`, `mother`, `key`; it is refused if the entry's final state is not the line's |
| `external` | (P5) a measurement not in PDG: c = value/BF_MC, σ_c = error/BF_MC, how `external`, flag `external`, `pdgids` = `external:<source>`. Refused once PDG has an exact or product entry for the final state |

*On the particle names.* Both `description` and the quoted text in `reason` use **PDG's** spelling,
because `description` is parsed like any PDG text. The four spellings you noticed are PDG's own, in
one and the same entry: PDG writes `Dbar_2^*(2460)-` in the first half and `D^*_2()-` in the second.
PDG's bar marks the charm content (an anti-charm meson), which is redundant once the charge is
given, and PDG itself is not consistent about it. The parser accepts all of them and maps them to
one particle of `evt.pdl`, `D_2*-` (code −415). The name table (`PDG_NAMES` in `pdg_match.py`) was
checked entry by entry against `evt.pdl` in the review.
