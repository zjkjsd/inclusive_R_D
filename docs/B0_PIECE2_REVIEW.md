| `max_share` | review file only: the largest share of the exclusive yield that this mode has in any of the 72 sample tables (12 samples × comb D side, comb ℓ side, hadB × charged, neutral) |

| `n_top95` | in how many of the 72 tables the mode is among those that cover 95 % of the exclusive hadronic yield |
| `why` | why the row is in the review: `top95` (large yield), `pull` (c more than 3σ from 1), `flag` (carries a warning) |

Flags: `tau` (τ mode), `c_extreme` (c outside 1/3 … 3), `remainder_unstable` (the subtraction gave
no usable value, a cruder ratio was used), `node_not_closed`, `node_ambiguous`, `limit_capped` (the
line was kept at c = 1 because a c would push it above its own PDG limit), `above_limit` (the decay
file is above a PDG limit), `resonance_mismatch`, `multi_ks` (several K_S: no c), `flavor_twin`,
`block_asymmetric` (the B and anti-B blocks of the decay file differ for this mode),
`exception_applied`, `zero_bf` (a zero-rate veto line).

## 2. Method points

### M1. Order of the sources

*Terms.* A **product entry** is a PDG entry for a decay chain, quoted as one number:
B(B⁰ → D₁⁻ ℓ⁺ν) × B(D₁⁻ → D̄\*⁰π⁻) = (2.85 ± 0.25)·10⁻³. A **multi-body entry** ("node") is a PDG
entry for a final state, whatever produced it: B(B⁰ → D̄\*⁰π⁻ ℓ⁺ν) = (5.44 ± 0.28)·10⁻³. This one
*includes* D₁, D′₁ and D₂\* decaying to D̄\*⁰π⁻, plus any non-resonant part.

*Why the order matters.* The decay-file line D₁⁻ ℓ⁺ν appears in both entries: directly in the
product entry, and as one of several contributors to the multi-body entry. One of the two has to
set its c.

- Multi-body entry first (the plan as written): D₁, D′₁ and D₂\* ℓν all receive the *same* c = 0.74,
  the ratio of the D̄\*⁰π⁻ℓν entry to the sum of everything in the decay file that feeds it.
- Product entry first (as implemented): each state gets its own c from its own measurement.

| B⁰ line | c, product first | c, multi-body first |
|---|---|---|
| D₁⁻ ℓ⁺ν | 0.96 ± 0.07 | 0.74 ± 0.04 |
| D′₁⁻ ℓ⁺ν | 0.93 ± 0.21 | 0.74 ± 0.04 |
| D₂\*⁻ ℓ⁺ν | 0.84 ± 0.09 | 0.74 ± 0.04 |

*Recommendation.* Product first. It is the more specific measurement, and it gives what you expect:
a different c for each D\*\* state.

*Decision:* OPEN.

### M2. Non-resonant D(\*)π ℓν lines

*Facts.* The decay file has non-resonant lines B → D(\*)π ℓν (Goity–Roberts model, 0.092 % each for
the charged-pion modes). PDG has **no** measurement of the non-resonant part: its D(\*)π ℓν entries
are totals that include the D\*\* states. So the only way to get a c for these lines is by
subtraction: total minus the D\*\* products. That subtraction does not work (cases C2, C4, C8):

- D̄\*⁰π⁻ ℓν (C2): the three D\*\* products already add up to more than the total. Nothing is left;
  the code falls back to a crude ratio (c = 0.74) that has no physical meaning for this line.
- D̄⁰π⁻ ℓν (C4): the decay file's D₀\* ℓν is five times above PDG's upper limit, so it was held at
  c = 1; the subtraction then gives the non-resonant line c = 2.45.

*Options.*
1. Treat the non-resonant D(\*)π ℓν lines as **not measured** (class `none`, c = 1). They then
   belong with the gap modes, with a wide prior (piece 4). The D\*\* lines keep their product c.
2. Keep the subtraction results.

*Recommendation.* Option 1. It matches your statement that the D\*\* ℓν resonances and the
non-resonant D\*π ℓν must not be mixed, and it avoids numbers that only reflect inconsistencies
between PDG entries. Implemented as one exception per entry ("do not derive c for non-resonant
lines from this total").

*Related question for you.* B⁰ → D₀\*⁻ ℓ⁺ν: the decay file has 0.362 % × B(D₀\* → D̄⁰π⁻) 0.667 =
0.241 %; PDG gives an upper limit of 0.044 % for this product (S042.418). In B⁺ the same product is
measured, (0.090 ± 0.054) %, c = 0.35 ± 0.21. Should the B⁰ line follow the B⁺ measurement
(isospin), stay at c = 1 with a wide prior, or be scaled to the limit?

*Decision:* OPEN.

### M3. Which c may become weights

AGREED in principle (2026-11-16): c from exact and product matches, and from node matches without a
warning flag, are candidates for weights; flagged modes keep c = 1 with a wider prior. The flagged
cases are discussed one by one first (section 5). Final rule: piece 4.

### M4. PDG table for D decays

*Question.* Should the D-meson branching fractions be cached and compared as well?

*Facts.* The B-level comparison does not need them: the stored truth is the B's direct daughters.
What the D decays do affect:

- D⁺ → K⁻π⁺π⁺ (decay file 9.38 %): a common factor of every component with a D⁺, signal and
  normalization included. It largely cancels in R(D).
- The chains that end in a D⁺: D\*⁺ → D⁺π⁰/γ (32.3 % in the decay file), D\*\* → D(\*)π, D_s\*\* → D K.
  A wrong value there changes how many D⁺ a given B decay delivers. This acts the same way on all B
  modes with that parent.
- Inclusive D → K_L X and D → ℓ X rates: these matter for the K_L check (Part C) and for the
  cascade leptons, not for B0.

*Recommendation.* Not now. For Part B a short check of the few chain BFs listed above against PDG
is enough (an hour of work, a table in the working document). A cached D table becomes useful for
Part C (K1 needs the inclusive D → K⁰ X rates) and can be built then with the same code
(`build_pdg_table` takes the PDG identifier of the parent).

*Decision:* OPEN.

## 3. The exceptions file

`Samples/dec/pdg_exceptions.json` holds the corrections to the automatic matching. Each entry names
a PDG entry (`pdgid`), an `action` and a `reason`. It is read every time the table is built; without
an entry, the automatic rule applies. Actions:

| Action | Effect |
|---|---|
| `rewrite` | the text of the PDG entry is replaced by `description` before it is parsed. For misprints and incomplete texts in the PDG listing |
| `exclude_node` | the entry is not used at all |
| `fold` / `no_fold` | for one final-state entry: add or remove resonances that are counted as part of it |
| `force_class` | set the class of a final state by hand |

*On the particle names.* Both `description` and the quoted text in `reason` use **PDG's** spelling,
because `description` is parsed like any PDG text. The four spellings you noticed are PDG's own, in
one and the same entry: PDG writes `Dbar_2^*(2460)-` in the first half and `D^*_2()-` in the second.
PDG's bar marks the charm content (an anti-charm meson), which is redundant once the charge is
given, and PDG itself is not consistent about it. The parser accepts all of them and maps them to
one particle of `evt.pdl`, `D_2*-` (code −415). The name table (`PDG_NAMES` in `pdg_match.py`) was
checked entry by entry against `evt.pdl` in the review.

| # | PDG entry | Action | What it does and why | Effect | Status |
|---|---|---|---|---|---|
| E1 | S042.124, B⁰ → D₂\*(2460)⁻π⁺, D₂\*⁻ → "D⁰π⁻" | rewrite to D̄⁰π⁻ | A D₂\*⁻ (c̄d) decays to D̄⁰π⁻; "D⁰π⁻" would change charm by two units. PDG writes D̄⁰π⁻ in the neighboring entries | D₂\*⁻π⁺ gets c = 1.39 ± 0.09 from its product entry | OPEN |
| E2 | S042.385, B⁰ → D₀\*⁻π⁺, D₀\*⁻ → "D⁰π⁻" | rewrite to D̄⁰π⁻ | same misprint | D₀\*⁻π⁺ gets c = 0.27 ± 0.03 | OPEN |
| E3 | S042.100, B⁰ → D_sJ(2457)⁺ D\*(2010), D_sJ⁺ → D_s⁺γ | rewrite: D\*(2010)⁻ | PDG gives no charge for the D\*; charge conservation fixes it | adds a cross-check for D\*⁻D_s1⁺ (its c stays the exact one, 1.00) | OPEN |
| E4 | S042.511, B⁰ → D±D\*∓ (CP-averaged) = 6.14·10⁻⁴ | rewrite as the sum D\*⁺D⁻ + D\*⁻D⁺ | see D3 | both lines c = 1.01 ± 0.10 | OPEN (D3) |
| E5 | S042.155, B⁰ → D\*(2010)⁺D⁻ = 6.12·10⁻⁴ | exclude | see D3 | avoids c = 2 for one charge state | OPEN (D3) |
| E6 | S041.858, B⁺ → ψ(2S)K₁(1270)⁺, K₁ → K⁺π⁺π⁻ = 3.3·10⁻⁵ | exclude | listed next to "(P-wave)" 3.26·10⁻⁵ and "(D-wave)" 2.96·10⁻⁵ of the same decay; their sum exceeds it, so it is one component of an amplitude fit, not the total | ψ(2S)K₁⁺ gets c = 0.75 ± 0.09 from the ψ(2S)K⁺π⁺π⁻ total instead of 0.23 | OPEN |

## 4. The three modes that need a decision

### D1. B⁰ → D⁻ a₁⁺ (case C1)

- Decay file, line 697: 1.071 %, with the comment "Interpreting D3pi BF as fully (D- a1(->3pi))
  decay". With B(a₁⁺ → π⁺π⁺π⁻) = 0.5175 from the decay file this gives 0.554 % of D⁻π⁺π⁺π⁻.
- PDG entries:

| PDG entry | Value | Note |
|---|---|---|
| S042.88, D⁻π⁺π⁺π⁻ (total) | (0.598 ± 0.061) % | PDG fit, 10 % precision |
| S042.89, non-resonant part | (0.39 ± 0.19) % | old measurement |
| S042.91, D⁻π⁺ρ⁰ | (0.11 ± 0.10) % | old measurement |
| S042.93, D⁻ a₁(1260)⁺ | (0.60 ± 0.33) % | old measurement, 54 % error |

- The automatic rule takes the entry with the same particles, S042.93: c = 0.56 ± 0.30. After that
  the decay file has only 0.32 % of D⁻3π, 4.5σ below the total.
- Using the total instead: c = 1.06 ± 0.11.
- The mode is up to 15 % of the exclusive yield in one table.

*Options.* (1) total S042.88, c = 1.06 ± 0.11; (2) direct entry, c = 0.56 ± 0.30; (3) c = 1 with a
wide prior.

*Recommendation.* Option 1: it is the measurement the decay-file authors used, and by far the most
precise. Side effect to accept or not: excluding the old sub-entries S042.91 and S042.93 changes one
other line, D⁻K⁺K̄\*⁰ (0.058 %, share below 0.1 %), from c = 0.81 to 0.40; to be checked when the
exception is written. Separate remark: the decay file makes all D⁻3π through the a₁, while PDG's old
sub-entries suggest a sizeable non-resonant part. That is a shape question (`resonance_mismatch`
type), not a rate question.

*Decision:* OPEN.

### D2. B → D(\*) D_s0\*(2317)

| Line | Decay file | PDG product with D_s0\* → D_s π⁰ | c |
|---|---|---|---|
| B⁰ → D⁻ D_s0\*⁺ (790) | 0.738 % | (0.105 ± 0.016) % | 0.143 ± 0.022 |
| B⁰ → D\*⁻ D_s0\*⁺ (791) | 1.769 % | (0.150 ± 0.060) % | 0.085 ± 0.034 |
| B⁺ → D̄⁰ D_s0\*⁺ (4339) | 0.762 % | (0.079 ± 0.014) % | 0.104 ± 0.019 |
| B⁺ → D̄\*⁰ D_s0\*⁺ (4340) | 1.706 % | (0.090 ± 0.070) % | 0.053 ± 0.041 |

- The four decay-file values equal the PDG values of the D_s\*⁺ modes (D⁻D_s\*⁺ 0.738 %,
  D\*⁻D_s\*⁺ 1.769 %, …) to all digits: they were copied onto the wrong lines.
- The decay file sends D_s0\* → D_s⁺π⁰ in 100 % of the cases (D K is commented out). PDG gives
  B(D_s0\* → D_s π⁰) = 100 +0/−20 %, so c could be up to 25 % larger, still about 0.1.
- These modes are 2–10 % of the exclusive yield, and your `PDG_CORRECTIONS` already applies exactly
  these four ratios.

*Recommendation.* Keep them as weights, now with their uncertainties, and add the −20 % of the
sub-decay as an extra uncertainty on c. The D_s⁺π⁰ final state itself contains no D⁺ from the
D_s0\*, so the D⁺ in these events is the other D; the correction is a pure rate change.

*Decision:* OPEN.

### D3. B⁰ → D\*⁺D⁻ and D\*⁻D⁺

- Decay file, lines 613 and 614: 0.0305 % each, 0.061 % together.
- PDG has two entries: S042.155 "D\*(2010)⁺D⁻" = (6.12 ± 1.53)·10⁻⁴ and S042.511 "D±D\*∓
  (CP-averaged)" = (6.14 ± 0.58)·10⁻⁴.
- Read literally, S042.155 is one charge state: that line would get c = 2.0 and the other no c.
- Both PDG values equal the *sum* of the two decay-file lines. The experiments measure the two
  charge states together. So I read both entries as the sum: both lines c = 1.01 ± 0.10 (E4, E5).
- I could not check the wording of the PDG listing for S042.155 (the cached table has no footnotes).

*What I need from you.* A look at the PDG listing of B⁰ → D\*(2010)⁺D⁻: does it say that both charge
states are included? If you can't tell, the alternative is to keep E4 (the CP-averaged entry is
unambiguous) and E5 as a consequence.

*Decision:* OPEN.
